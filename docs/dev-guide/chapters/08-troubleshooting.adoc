== Troubleshooting

`kind` (or another tool) is not recognized::
Install it with `.\local\00-prereqs.ps1 -Install`. If it is installed but still not found,
the terminal has an old PATH: dot-source `local/env.ps1` again (it reloads PATH from the
registry) or restart IntelliJ.

kind cannot create the cluster::
The Podman machine is rootless. Run `local/01-podman-rootful.ps1`, then check with
`podman info --format "{{.Host.Security.Rootless}}"` (must be `false`).

`kubectl` or https://localhost:30443 cannot connect ("actively refused")::
Run `.\local\bridge.ps1` (always needed after a Podman machine or Windows restart).
+
Why: with a *rootful* Podman machine on WSL, published ports are kernel redirect rules with no
listening process, and WSL's localhost relay only forwards ports where a process is really
listening. `bridge.ps1` starts the `capa-bridge` socat container on the VM's host network, which
*is* a real listener, and forwards 6443 / 30443 / 30080 / 30088 / 30746 to the kind node.
+
[source,text]
----
Windows 127.0.0.1:6443 --(WSL relay)--> capa-bridge (socat) --> kind node :6443
----
+
Still failing: `.\local\diag-network.ps1` tests each hop separately.

Pod stuck in `ErrImagePull` / `ImagePullBackOff`::
The image was not loaded into kind, or the tag in `gitops/` does not match.
Run `kind load image-archive` again and compare tags. Never use `latest`:
Kubernetes then defaults `imagePullPolicy` to `Always` and tries a registry.

App is `OutOfSync` right after a sync::
Something in the cluster mutates a field (defaults, controllers). Look at `argocd app diff`;
if it is expected, add an `ignoreDifferences` entry rather than fighting it.

Machine needs more (or less) CPU / memory::
On WSL, Podman cannot size the machine (`--cpus`/`--memory` are QEMU-only). Edit
`%UserProfile%\.wslconfig` (`[wsl2]` section, `memory=` / `processors=`), then `wsl --shutdown`
and `podman machine start`.

`kubectl patch -p '{...}'` fails or does nothing in PowerShell::
Windows PowerShell 5.1 strips inner double quotes when passing arguments to native programs,
so inline JSON reaches `kubectl` broken. Put the patch in a file and use `--patch-file`
(see `local/argocd-server-nodeport.yaml`).
